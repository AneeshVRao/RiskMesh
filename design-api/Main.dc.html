The governing rulewhy the API computes almost nothing

Every score in this system is frozen. out/components.csv is the scorer's own output for all 100 candidate components, carrying raw, norm and detail for each of the 7 signals. The API's job is to read and reshape that, never to re-run score_component().

A live re-score would be the single most dangerous thing this service could do: it would let the number on screen drift from the number in the frozen record, and the whole project's discipline rests on those being the same number. The scorer is not imported by the API at all. If a score needs to change, the pipeline re-runs and re-freezes; the API just reads whatever is on disk.

Resolved · two new pipeline outputsout/ becomes the single runtime source

Decided: the API reads out/ and only out/. experiments/ is provenance and history, never a runtime data source, and the API special-cases nothing.

New file in out/Written byHow
out/weight_policy.json __main__.py, standard run Byte copy of experiments/weight_policy.json via shutil.copyfile. Never a json round-trip — re-serialising could reorder keys or change spacing and break byte-for-byte reproducibility on a file whose content did not change.
out/graph_edges.json __main__.py, standard run Adjacency built from the same in-memory components the scorer already holds, for flagged components only (score ≥ t_lo). Sorted node and edge lists so the serialisation is stable.

Both are generated inside the fingerprinted pipeline, so they inherit the same reproducibility guarantee as everything else. The graph is never reconstructed live in the API — that would put untested derivation on the request path and outside the fingerprint.

Fingerprint disciplinestructural, not advisory

Every artifact carries config_fingerprint. On startup the loader asserts all of them agree, and refuses to start if they do not — the same raise-don't-warn rule select_threshold() and select_abstention_band() already follow. A mixed-vintage API serving eval_report from one run and components.csv from another would be silently, invisibly wrong. Every response echoes the fingerprint so the UI can display which frozen run it is showing.
