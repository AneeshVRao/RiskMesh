riskmesh/api/
  __init__.py
  main.py       FastAPI app, CORS for the static UI, router mounts,
                startup artifact load + fingerprint assertion
  artifacts.py  THE ONLY READER of frozen files. Loads once at
                startup, caches, exposes typed accessors.
  schemas.py    Pydantic response models = the wire contract
  bands.py      score -> allow|review|escalate, and contribution
                = round(w * norm, 6). The 2 derived rules, isolated.
  rings.py      GET /rings, /rings/{id}, /rings/{id}/evidence
  analysis.py   GET /metrics, /threshold-analysis, /benchmark
  audit.py      THE ONLY WRITER. append() + tail(). Owns JSONL.
  review.py     POST /rings/{id}/review -> audit.append()
  explain.py    POST /explain. Stub returning fallback_used:true
                until and unless there is time.

Two modules touch the filesystem and nothing else does: artifacts.py reads, audit.py writes. Every route module consumes typed objects. That is what makes the “the API never re-scores” rule checkable rather than merely intended — riskmesh.score appears in no import line under api/.

Why these seamseach module is one reason to change

ModuleExists because
artifacts.pyIf the frozen files move or gain a field, exactly one file changes. It is also where the fingerprint assertion lives, so a mixed-vintage load cannot reach a route.
bands.pyHolds the only two formulas the API owns. Isolating them means they can be unit-tested against abstention.py's own values — the API's band logic must agree with the pipeline's, and a test can prove it does.
audit.pyThe single writer, behind append() / tail(). This is the seam that makes the JSONL→SQLite swap a one-file change if it ever becomes necessary.
schemas.pyThe response contract is the thing the four UI pages actually depend on. Keeping it in one file means the mockups' data needs and the API's output can be diffed by reading one screen.
explain.pySeparate so it can be deleted, or left as a permanent fallback stub, without touching a route the UI depends on.
