# Frozen experiment records

Rejected-alternative provenance for RISK-003. `out/` is gitignored, so these are
the durable copies — the E1 and E3 records are kept permanently even though both
were rejected, because they are the evidence for why the adopted design (E2)
looks the way it does.

Each record was written *before* the held-out split was read; `held_out_view()`
in `riskmesh/experiment.py` refuses to hand over test components until the file
exists on disk.

| file | change | ring-family | pos-below-max-neg | held-out F1 | outcome |
|---|---|---|---|---|---|
| `experiment_e1.json` | household co-burst removed | +0.2422 | 0.2500 | 0.800 | rejected — destroys the hard negative |
| `experiment_e2.json` | household co-burst at independent merchants | +0.1953 | 0.5625 | 0.800 | **adopted** |
| `experiment_e3.json` | overlapping household merchant pools | +0.2188 | 0.2500 | 0.7619 | rejected — fails criterion 4 |
| `experiment_e4.json` | ring instrument overlap scales with ring size (RISK-004) | -0.0391 | 0.6875 | 0.800 | rejected — fails criteria 1 and 2 |
| `experiment_e5.json` | component-relative instrument concentration (RISK-004 option 1) | -0.2263 | 0.5625 | 0.800 | rejected — worse than the definition it replaces |
| `experiment_e6.json` | ring funding pool + accounts-per-card feature (RISK-004 option 2) | +0.1576 | 0.0625 | 0.8889 | rejected — over-separates, panel FAILS |

The `ring-family` column is the delta on the signal each experiment targets:
`temporal_burst` for E1-E3, `instrument_sharing` for E4.

`ablation_temporal_burst.json` is not an experiment -- it is the Tier 1
ablation gate, a single measurement with no acceptance band. It found
`temporal_burst` **redundant**: removing it and renormalising the other six
leaves held-out precision, recall, F1 and FPR unchanged and flags the same 12
components. See `implementation_plan.md`.

`weight_policy.json`, `abstention_policy.json`, `xgboost_policy.json` and
`graphsage_policy.json` are frozen *policy* records rather than experiments:
each is regenerated by `riskmesh/freeze.py` (`python -m riskmesh.freeze
{weights,abstention,xgboost,graphsage,all}` — see Task 1's report for why
this entry point exists: before it, nothing regenerated these four files and
they were byte-copied from disk with no way to reproduce them), written
before its single held-out read, and carries that read's result in a
`held_out` block (`null` for `xgboost_policy.json`, since no XGBoost
candidate is feasible on the current benchmark — see below).

Current fingerprint across all four: **`fdf4fc217347d36b`** (Task 6's
re-freeze against the Tasks 3-4 benchmark — 5 ring types, 4 hard-negative
cluster types, 19,310 transactions). The table below replaces one that quoted
Phase-12 figures (threshold 0.23, F1 0.8000, band 0.23/0.33) that no longer
exist in any of these four files.

| file | selects | protocol | held-out result |

| `abstention_policy.json` | the review band `(t_lo, t_hi)` over the frozen scorer, by minimising expected validation loss | `abstention_protocol.md` | `t_lo` 0.10 / `t_hi` 0.20 (the first non-degenerate band this project has selected — every prior run collapsed to `t_lo == t_hi`); three-way expected loss **75,529.35** against the binary policy's 92,263.55 on the identical rows, an **18.1% improvement** |

`out/threshold.json` is a **separate** selection (`select_threshold()`,
maximises F1 rather than minimising expected loss) and is not one of these
four records — it lives in `out/` because it is regenerated on every plain
`python -m riskmesh` run, not only by `riskmesh/freeze.py`. Do not read
`weight_policy.json`'s threshold (0.10) and `out/threshold.json`'s threshold
(0.22) as the same number; they answer different questions. See README's
"Two Tier 1 operating points" for both figures side by side and
`deferred_decisions.md` D4 for the PRD compliance gap this distinction opens.

Full reasoning: `bugs.md` RISK-003/RISK-004, `deferred_decisions.md` D1
(closed by the current re-freeze) and D4 (new), and each protocol's own §8.

Regenerate any of the four policy records with `python -m riskmesh.freeze
{weights,abstention,xgboost,graphsage}`, or all four with
`python -m riskmesh.freeze all`.

Regenerate any of the six numbered experiments (E1-E6, below) with
`python -m riskmesh.experiment {e1,e2,e3,e4,e5,e6}` (the CLI's own `choices`
list also accepts `ablation`, for `ablation_temporal_burst.json`). Note that E2 is now the
default config, so `run_e2`'s baseline-vs-experiment comparison reads
differently than it did when the record was first frozen; the frozen file
is the record of the original run.
