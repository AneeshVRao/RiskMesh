# Tier 0 has zero runtime dependencies on purpose.
#
# "Reproducible from a clean environment" is a graded PRD criterion, and the
# cheapest way to guarantee it is to need nothing but CPython >= 3.10. Union-find
# is ~15 lines (cheaper than networkx) and the CSVs written to out/ are
# pandas-readable whenever Tier 2 actually needs pandas.
#
# Do not add a dependency here without moving the decision in
# implementation_plan.md first. numpy/pandas/xgboost arrive with Tier 2.

# --- API layer only (Tier 1 investigator console) -------------------------
# Decision recorded in implementation_plan.md, "Tier 1 - investigator console
# API". The PRD names FastAPI in Technical Specifications.
#
# Tier 0's zero-dependency guarantee is NOT weakened: `python -m riskmesh` and
# tests/test_riskmesh.py still import nothing outside the stdlib, and so do the
# API's own data modules (artifacts, bands, payloads, audit) plus
# tests/test_api.py. Only riskmesh/api/routes.py and main.py need these.
fastapi
uvicorn

# --- XGBoost scorer only (Tier 2) ------------------------------------------
# Decision recorded in implementation_plan.md, "Tier 2 -- XGBoost scorer".
# Tier 0's zero-dependency guarantee is still not weakened: `python -m
# riskmesh` and tests/test_riskmesh.py import nothing outside the stdlib.
# numpy and xgboost are confined to riskmesh/ml.py and tests/test_ml.py.
#
# Reproducibility caveat, same shape as config.py's docstring scoping Python's
# own `random` module to "one interpreter version": xgboost's internal RNG and
# tree-building are not guaranteed bit-identical across library versions.
# Every frozen record ml.py produces carries the installed xgboost.__version__
# alongside sys.version, for the same reason.
numpy
xgboost

# --- GraphSAGE-style GNN scorer only (Tier 3, stretch) ----------------------
# Decision recorded in implementation_plan.md, "Tier 3 -- GraphSAGE scorer",
# and in task_today.md's "Dependency decision". Tier 0's zero-dependency
# guarantee is still not weakened: `python -m riskmesh` and
# tests/test_riskmesh.py import nothing outside the stdlib. torch is confined
# to riskmesh/gnn.py and tests/test_gnn.py.
#
# CPU build only -- no GPU tooling. torch_geometric and dgl are deliberately
# NOT added: the GraphSAGE aggregation (sample/aggregate neighbours,
# concatenate with the node's own features, one linear layer, repeat) is
# hand-rolled with plain tensor operations in riskmesh/gnn.py, the same
# preference riskmesh/graph.py's own docstring states for union-find over
# networkx -- a full graph-ML library is unjustified weight for a ~105-graph,
# mostly-under-10-node dataset.
#
# Reproducibility caveat, same shape as the xgboost one above: neural-network
# training has run-to-run variance beyond what a fixed seed alone controls in
# general. Every frozen record gnn.py produces carries the installed
# torch.__version__ alongside sys.version, for the same reason.
torch
